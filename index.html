Before the app runs

A JavaScript supply-chain attack does not need to wait for your code path. It can arrive in a package version, a lifecycle script, a cache entry, or a developer tool that runs with more authority than the app it helps build.

Method

The scanner looks at state, so the state had to be staged.

The public CLI always scans local package-manager state. For this story, each package/version was resolved into an isolated install root with lifecycle scripts disabled, then scanned with the same advisory engine.

Scan matrix

Most rows were clean. The risk was concentrated in windows.

Each cell is one exact package version tied to a popular JS/TS GitHub project. Larger dependency surfaces gave attackers more places to hide, while the sharpest matches clustered around poisoned release windows.

Incident timeline

Publishing access became the pressure point.

The scanner snapshot tracks eight advisories, from Nx and Rspack through Axios and Mini Shai-Hulud. The largest campaigns were not single vulnerable functions; they were poisoned release events.

Registry/source split

The package is the crime scene, not always the repo.

Maintainer-account and token compromises can publish a poisoned artifact under a trusted name. A GitHub tag can look ordinary while the npm registry serves a version teams should treat as exposed.
